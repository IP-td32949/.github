<h2>从网络拓扑开始想，而不是从软件设置开始</h2>
<p>搭建跨境电商的静态住宅网络环境，多数教程从「打开设置填代理」开始。这个起点太低，容易导致后面反复返工：设备一多就要逐台配，规则不一致，某台设备漏配也没人发现。</p>
<p>更合理的起点是网络拓扑：这套环境要服务几台设备、要不要分流、出口怎么分配。拓扑定了，配置才有章可循。</p>

<p>逐台配置的问题是规则分散。三台以内还能管住，超过之后必然出现不一致。网关分流把规则集中到一处，是规模化的起点。</p>

<h2>网关分流怎么搭</h2>
<p>三层结构。出口层：多条静态住宅地址。接入层：一台能做策略路由的设备，负责按规则选出口。终端层：各设备连到网关，不单独配置。</p>
<p>配置顺序：先定出口参数，再定内网网段，再写映射规则，最后逐设备验证。顺序错了会互相覆盖。</p>

<h3>映射规则怎么写</h3>
<p>按内网地址映射最稳。给每台设备固定内网地址，然后写「内网地址 → 出口地址」的规则。这样设备换位置也不影响出口分配，因为规则跟着地址走。</p>
<h3>DNS 要在网关统一改</h3>
<p>把 DNS 设为目标地区解析，并在网关上强制，避免某台设备自行设置导致泄漏。这是网关方案的一个明显优势：终端无法绕过。</p>

<h2>出口层怎么规划</h2>
<p>按经营主体规划，不按设备数。一个主体一条出口，同一主体下的多台设备可以共用一条。这样既保证隔离，又不会因为设备多而成本暴涨。</p>
<p>同时预留一到两条备用出口，用于故障替换。备用不必长期高配，能应急即可。</p>

<h2>终端层要做什么</h2>
<p>三件事。一，固定内网地址。二，统一时区与语言，与出口地区一致。三，独立浏览器环境，每账号一份。</p>
<p>第一项是网关方案的前提。设备用动态地址时，映射规则会失效，表现为「今天对明天错」。</p>

<h2>验证与巡检</h2>
<p>验证四项：出口正确、解析正确、目标平台可正常登录、连续运行不掉线。</p>
<p>巡检两件事：核对实际出口与台账是否一致、核验是否有设备绕过网关直连。第二项尤其重要，有人手动改了 DNS 或装了别的客户端，流量就漏走了。</p>

<h2>常见故障</h2>
<p>故障一，某台设备出口不对。多为该设备有固定 DNS 或固定网关，绕过了规则。</p>
<p>故障二，全部设备变慢。多为出口带宽被某一台设备占满。做限速可以缓解。</p>
<p>故障三，时断时续。多为网关性能不足或连接数触顶。设备数多时需要考虑网关规格。</p>
<p>故障四，出口偶发漂移。多为 DHCP 重新分配导致内网地址变化，映射失效。</p>

<h2>成本与规模的平衡</h2>
<p>网关方案的前期投入比逐台配置高，但边际成本低。设备从三台增到十台，逐台配置的工作量线性增长，网关方案几乎不变。</p>
<p>因此拐点大致在三到五台之间。低于这个数量，逐台配置更省事；高于这个数量，网关方案开始划算。</p>

<p>搭建完成的标准不是「能打开目标网站」，而是三处一致：出口地址、DNS 解析位置、系统时区语言。三者只要有一处对不上，环境就不算干净。验收时逐项截图存档，后面出现异常可以直接对比，这比凭记忆判断快得多。</p>
<h2>常见问答</h2>
<h3>必须买专用设备吗</h3>
<p>不必。软路由或一台小型主机就能承担。关键是支持策略路由与稳定的长时间运行。</p>
<h3>网关会不会成为单点故障</h3>
<p>会。所以关键业务建议准备备用网关，或至少有快速恢复的配置备份。</p>
<h3>能远程管理吗</h3>
<p>可以，但要限制来源地址，不要把管理界面暴露在公网。</p>
<h3>改配置要不要停机</h3>
<p>多数规则调整可以热生效，不影响已建立的连接。改动前备份配置，出问题能快速回退。</p>
